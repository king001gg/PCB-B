# 彩色相机接入后的待标定项清单

日期：2026-09-20
适用：海康彩色工业相机（MVS / 官方 SDK 路线）

## 一句话

代码侧已经改完（驱动自适应彩色、对话框不再吞掉 Bayer、白平衡已关闭），
但 `config/default.yaml` 里的值**全部绑在旧相机 + 旧镜头 + 旧光源这条链上**。
不重标就换相机，检测结果不可信，而且**不会报任何错**——这是最危险的地方。

按 A → B → C 的顺序做。A 是阻断项，B 依赖 A（A 没定，拍出来的样本就没有可比性）。

---

## A. 相机侧（阻断项，先做）

改 `config/default.yaml` 的 `camera` 节 + `system.resolution_mm_per_pixel`。

| # | 配置项 | 当前值 | 为什么必须改 | 怎么定 |
|---|---|---|---|---|
| A1 | `camera.device.serial_number` | `""`（空串） | 留空 = 取枚举到的第一台。网口插拔顺序会变，**多机时直接拍错工位** | `python tools/check_camera.py --list-only` 列出 model / SN / IP，把新彩色机的 SN 填进来 |
| A2 | `camera.pixel_format` | `"BGR8"` | 占位值，没验过新机是否支持 `BGR8_Packed` 输出。不少海康彩色机原生只出 Bayer，不提供打包输出 | 连上后看读回的真实值，以读回值为准 |
| A3 | `camera.width` / `camera.height` | `2448` / `2048` | 旧机分辨率。不一致时相机会按对齐要求**夹取**，配置里写的和实际生效的不是一回事 | 用新机实际能力，然后核对读回值 |
| A4 | `system.resolution_mm_per_pixel` | `0.01` | 绑在**镜头 + 工作距离**上，不绑在相机上。换相机通常也换了镜头或工作距离。被 `core/defects.py:407`（缺陷面积 mm²）、`core/quality.py:173`、`core/color.py:243`（越界区域面积 mm²）三处使用 | 拍一把刻度尺或标定板，量图上 N 像素对应的实际毫米数 → `mm_per_px = 实际mm / N` |
| A5 | `camera.exposure_us` / `camera.gain` | `5000` / `1.0` | 彩色机有拜耳滤镜，每个像素只过一个颜色，灵敏度低于同规格黑白机。同样光照下需要更长曝光或更高增益 | 对着良品样本调，目标是铜面不过曝、暗部有细节 |

**A2 的验证方式（最容易出错的一条）**：GUI「相机设置 → 测试连接」会打印**通道数**。

- 显示 `3` → 彩色路径通了
- 显示 `1` → 实际落到 Mono8 了，色度指标会**全程跳过**并在报告里标注「色度未测」

配置值 ≠ 读回值时，以读回值为准（相机按能力夹取不是错误，是它的正常行为）。
读回接口是 `MvsCamera.get_actual_params()`（`hardware/mvs_camera.py:684`）。

**A4 顺带查出来的问题**：`system.board_width_mm: 200` / `board_height_mm: 150`
**全仓库没有任何代码引用**，是条死配置。而 A4 的当前值下整幅视野只有
`2448 × 0.01 = 24.5mm`，和标称的 200×150mm 板子差 8 倍。标定 A4 时一并确认
面积百分比到底以哪个口径为分母，要么改这两个数、要么把它们删掉。

## B. 算法侧（必须在 A 定完之后做）

改 `inspection.color.absolute` / `inspection.color.adaptive`。

### B1. 色度绝对基线（最关键）

```yaml
absolute:
  hue_baseline_deg: 34.0   # ← 重标
  sat_baseline: 178.0      # ← 重标
```

**当前的值的来历**：实测**一张合成图** `BGR(60,140,200)` 的 H=17（OpenCV 单位）×2 = 34°、
S=178。这不是现场良品样本的统计量，是造图时凑出来的数。

换彩色机后彻底失效——拜耳阵列的光谱响应、新光源色温、相机内的白平衡，
任何一个都会整体平移 H。

**怎么定**：

1. 用新彩色机拍 **≥30 块良品板**（`data/samples` 里那 12 张是 600×800 的合成图，
   `board_01_simple.jpg` 之类，**不能用来标定**）
2. 每块跑一遍检测，导出报表 CSV，取 `color_hue_mean_deg` 与 `color_sat_mean` 两列
   （`core/quality.py:102-104`，`data/export.py:54-57`）
3. 基线 = 均值；容差 = 3σ（或 MAD × 1.4826，与 `adaptive.mad_k` 同源）

```yaml
  hue_tolerance_deg: 25.0  # ← 用上面的分布重定，不要沿用
  sat_tolerance: 50.0      # ← 同样来自那张合成图（铜面 ROI 窗口半宽×2、亮金 S 的 28%）
```

### B2. 自适应判据的结构性下限

```yaml
adaptive:
  mad_k: 3.0              # 阈值 = 3 × 1.4826 × MAD，与 SPC 3σ 同源
  min_hue_tol_deg: 8.0    # 圆中位数有 2° 量化下限，取其 4 倍防阈值退化到量化噪声
  min_sat_tol: 20.0       # 防整板极均匀时阈值过紧
  min_valid_pixels: 1000  # 有效色相像素少于此值 → 自适应判据本帧留空
```

这几个是**结构性下限，不随相机变**，但松紧对不对要等 B1 定了才能看：

- 跑一批良品，若 `color_oor_adaptive_pct` 恒为 `0` → 太松（该报的不报）
- 若良品就报出几个百分点 → 太紧（误报）

### B3. `inspection.color.hue_s_min: 30`

只对 `S ≥ 30` 的像素做色相统计（近中性像素的 H 由最低位抖动决定，是纯噪声）。
新机 + 新光源下铜面的 S 分布变了：若多数像素 `S < 30`，有效像素会跌破
`min_valid_pixels`，自适应判据**全程留空且不报错**。

验证：跑一张良品图，检查有效色相像素数是否远大于 1000。

## C. 与相机无关、但也还没标定的

这几项在配置里都标着「临时标定值」或「占位值」，是**同一批**工作，建议一起做：

| 位置 | 内容 | 标注 |
|---|---|---|
| `inspection.process_monitor.thresholds` | GLCM 报警阈值 `0.08 / 0.11 / 0.22`、`speed_base: 0.5` | `default.yaml:70`「临时标定值，尚未用现场数据验证」 |
| `inspection.defects.oxidation` | `h_range: [10,30]`、`s_min: 25`、`v_min: 35` | 另有语义矛盾未解：模块 docstring 说这是「正常金色铜面」的色相区间，配置注释说是「氧化色相范围（背离金色铜面）」——同一区间两种对立含义 |
| `inspection.defects.embedding` / `.unroughened` | `threshold_binary: 30`、`energy_threshold: 0.12` | 同上 |
| `inspection.quality` | 五个容忍上限 + `ok_score_threshold: 60` | 直接决定 OK/NG |
| `inspection.roi.copper_hsv_*` | `[0,30,60]` / `[25,255,255]` | 默认关；启用前需确认 |

## 建议执行顺序

1. **关掉 MVS 客户端**。它会独占相机——实测报 `0x80000203`（访问被拒绝），
   让 `tests/test_acquisition.py::test_real_camera_roundtrip` 跳过
2. `python tools/check_camera.py --list-only` → 拿新机 SN
3. 填 A1，确认 A2 / A3，跑 GUI「测试连接」**确认通道数 = 3**
4. **在 MVS 客户端里对着标准白板做一次白平衡**，做完会存进相机
   （软件侧已设 `BalanceWhiteAuto = Off`，只负责别把它改掉——
   设 `Once` 会在正在检测的板子上算白平衡，把被测色偏当校准目标消掉）
5. 调 A5 曝光/增益
6. 拍标定尺定 A4
7. 拍 ≥30 块良品 → 统计 → 定 B1 / B2 / B3
8. 复跑，确认自适应判据的误报率可接受
9. 同批把 C 里的阈值一起重定

## 验收基线

标定改动不应破坏现有测试：

```
python -m pytest -q
# 期望：1318 passed, 2 skipped, 33 xfailed
```

配置是纯数据改动，测试全绿说明没有代码被误伤——**但这不代表标定是对的**。
标定对不对只能看现场良品/不良品的分离度。
